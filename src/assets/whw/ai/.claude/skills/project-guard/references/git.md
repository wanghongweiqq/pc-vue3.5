# Git 操作规范

## 检查流程

按顺序执行所有检查，收集结果后统一按格式输出。

### 1. 当前分支确认
- 执行 `git branch --show-current`
- ✅ 非保护分支 → 通过
- ⚠️ 在 `master`/`main` 上 → 警告

### 2. 未完成改动检查
- 执行 `git status`
- ✅ 工作区干净 → 通过
- ⚠️ 有未暂存的改动 → 警告
- ⚠️ 有未提交的暂存 → 警告

### 3. 远端同步检查
- 执行 `git status -uno`
- ✅ 与远端同步 → 通过
- ⚠️ 本地落后于远端 → 警告

### 4. 输出检查列表 + 解决方案

```
## 检查结果

- [状态] 当前分支：<branch-name>
- [状态] 工作区状态：<干净 / X 个文件未暂存 / X 个文件待提交>
- [状态] 远端同步：<已同步 / 落后 N 个提交>
```

有 ⚠️ 时输出解决方案（带编号）：

**在保护分支上操作：**
```
问题：当前在 master/main 分支，不建议直接操作
> 1. 新建并切换 feature 分支
>    git checkout -b feature/<your-branch-name>
> 2. 继续在当前分支（风险自担）
```

**有未暂存改动：**
```
问题：工作区有未暂存的改动
> 1. 暂存所有改动
>    git add .
> 2. 暂存指定文件
>    git add <file>
> 3. 临时储藏（稍后再处理）
>    git stash
```

**本地落后远端：**
```
问题：本地落后远端，push 前建议先同步
> 1. rebase 方式同步（推荐，保持线性历史）
>    git pull --rebase
> 2. merge 方式同步
>    git pull
```
