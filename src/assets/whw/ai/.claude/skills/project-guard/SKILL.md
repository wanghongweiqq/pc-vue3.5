# project-guard — 项目修改前渐进式校验

## 核心原则

**渐进式披露**：根据用户意图，只加载并执行与当前操作相关的检查，不堆砌无关信息。

**输出格式规范**：所有检查结果必须按以下格式输出：

```
## 检查结果

| 检查项 | 状态 | 说明 |
|---|:---:|---|
| 检查项名称 | ✅/⚠️/❌ | 简短说明 |
| 检查项名称 | ✅/⚠️/❌ | 简短说明 |

## 解决方案         ← 仅当有 ⚠️ 或 ❌ 时才输出此节

**问题：<问题描述>**

| 推荐 | 数字选项 | 方案 | 命令 |
|:---:|:---:|---|---|
| 🟢 | 1 | <方案一描述> | `<命令>` |
| | 2 | <方案二描述> | `<命令>` |

输入数字选项，回车执行。
```

- ✅ 全部通过时：输出检查列表后直接给出正确命令，无需用户确认
- 有 ⚠️/❌ 时：输出检查列表 + 解决方案表格（第一行标注 `← 推荐`），等待用户输入数字
- 用户输入数字后：立即执行对应方案的命令
- 命令较长时可拆成多行展示在表格下方的代码块中，表格仅显示方案名

---

## 第一步：识别意图

读取用户输入，判断属于以下哪种操作类型，然后跳转到对应检查流程：

| 意图关键词 | 操作类型 | 跳转 |
|---|---|---|
| install / yarn add / npm i / 安装依赖 / 添加包 | 依赖安装 | → [依赖安装检查](#依赖安装检查) |
| uninstall / yarn remove / npm uninstall / 卸载 | 依赖卸载 | → [依赖安装检查](#依赖安装检查)（同一流程）|
| 改代码 / 写代码 / 修改文件 / 新增功能 / 实现 / 重构 | 代码修改 | → [代码修改检查](#代码修改检查) |
| git push / 提交 / commit / push / merge | Git 操作 | → [Git 操作检查](#git-操作检查) |

如果意图不明确，直接问用户："你打算做什么操作？（安装依赖 / 修改代码 / git 操作）"

## 扩展说明

后续可通过以下方式添加规范：

1. **新增架构规范**：在 `references/` 目录下新建 `<架构名>.md`，并在上方"加载对应规范"表格中添加一行
2. **项目级约束**：直接写入项目的 `specs/constraints/` 目录，guard 会自动读取
3. **全局约束**：写入本 skill 的 `references/global-constraints.md`（如需创建）
